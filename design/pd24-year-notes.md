# PD-24 — Year: три варианта полотна, на выбор владельцу

Артефакт: `design/pd24-year-variants.html` (автономный, переключатели внизу), скриншоты
`design/pd24-shots/`, скрипт съёмки `design/pd24-shots.mjs`.
Дизайн без реализации: в приложение ничего не вносится.

Визуальный язык взят целиком из утверждённого макета `pd7-board-variants.html` (вариант B Boxes):
те же токены, те же чернила #3B48B0 / #8C96FF, тот же сургуч #B3261E / #FF6B5E, тот же сгруппированный
фон (#F2F2F7 / #000) с приподнятой поверхностью (#FFFFFF / #1C1C1E), тот же стеклянный таб-бар с
фолбэками, только `system-ui` / `ui-serif`. **Ни одного нового цвета** — все оттенки на экране это
чернила, сургуч, системный серый или вычисленная смесь чернил/сургуча с поверхностью под ними.

## 1. Что кодирует картинку (одинаково во всех трёх вариантах)

Сознательное требование: **одно значение — один канал**, и ни одно значение не держится на цвете.

| Канал | Значение | Как выглядит |
| --- | --- | --- |
| Форма заливки | завершённость | полный квадрат = решено · нижняя половина = начато и брошено · только контур = пропущено · пусто = день в будущем **или до начала пользования** |
| Цвет | были ли исправления | чернила = день прошёл чисто · сургуч = были исправления |
| Срез угла | были ли исправления (дубль формой) | у «сургучного» дня срезан правый верхний угол |
| Тон (опция, по умолчанию выкл.) | решено с помощью | 62 % чернил вместо 100 % |
| Кольцо | сегодня | кольцо чернил вокруг клетки — ровно то же кольцо, что у выбранной клетки поля |

**Почему у исправлений два канала сразу (цвет + срез).** Чернила #3B48B0 и сургуч #B3261E дают друг
против друга **1.17:1** — они одинаково тёмные. Для ахроматопсии и на солнце эти два квадрата
неразличимы, а `accessibility.md › Color and effects` требует не оставлять смысл на одном цвете.
Срез угла решает это бесплатно и работает в обеих темах. По той же причине срез — единственный
носитель смысла в режиме «Nick only» (переключатель `Corrections`).

**Контрасты (посчитаны из hex, не оценены на глаз; поверхность — #FFFFFF в светлой, #1C1C1E в тёмной):**

| Метка | Светлая | Тёмная |
| --- | --- | --- |
| Решено (чернила) | #3B48B0 — **7.66:1** | #8C96FF — **6.42:1** |
| С исправлениями (сургуч) | #B3261E — **6.50:1** | #FF6B5E — **6.10:1** |
| С помощью (чернила 62 %) | #8589CE — **3.11:1** | #6168AA — **3.30:1** |
| С помощью + исправления (сургуч 62 %) | #D07874 — **3.17:1** | #B14D46 — **3.11:1** |
| Пропущено (контур) | #C6C6C8 — **1.71:1** (см. ниже) | rgba(235,235,245,.22) |

Изначально «с помощью» задумывался как 45 % чернил — это даёт **2.18:1**, ниже порога 3:1 для
значащей графики. Поднято до 62 %, минимальное значение, которое проходит. В `prefers-contrast: more`
тон поднимается до 78 % (#6670C1, 4.42:1), контур пропуска — до 55 % (#949497, **3.02:1**).

## 2. Три варианта раскладки

- **A. Ledger** — 12 строк-месяцев × 31 столбец-день, названия месяцев в левом жёлобе. Клетка ≈ 8 pt.
  Самый «журнальный» и самый простой для чтения «какое число». Занимает ≈ 356 pt по высоте — под ним
  остаётся ~200 pt воздуха.
- **B. Ribbon** — год как одна непрерывная сетка недель (7 строк), сложенная в два полугодовых
  полотна по 26–27 недель. Клетка ≈ 11 pt. Самый «тканевый»; риск: это ровно раскладка
  contribution-graph GitHub, плюс она невольно подсвечивает ритм недели — а ритм недели владелец
  отверг как механику.
- **C. Blocks** — 12 карточек-месяцев 3×4, внутри каждой сетка 7×5 по дням подряд. Клетка ≈ 12.4 pt.
  Это буквально девять боксов утверждённого поля, выросшие до двенадцати: та же приподнятая
  поверхность, тот же радиус, та же логика «структура задаётся пространством, а не линиями».
  Занимает ≈ 456 pt — единственный, который заполняет экран целиком без прокрутки.

Дни внутри месяца в C выложены подряд (1–7, 8–14, …), а не по дням недели: календарная выкладка
подсветила бы «ритм недели», которого в продукте намеренно нет, и дала бы рваные края у каждого
месяца вместо ровного прямоугольника.

### Рекомендация — **C. Blocks**

1. Это единственная раскладка, выведенная из уже утверждённого: боксы поля → боксы месяцев. Экран
   Year не выглядит приложением из другой вселенной.
2. Клетка 12.4 pt против 8 pt в A — качество дня реально видно, срез угла читается.
3. Месяц — это и есть цель тапа (115 × 108 pt), без единой натяжки по размеру элемента управления.
4. Заполняет экран без прокрутки: «год одним взглядом» выполняется буквально.

A держу как запасной (если владельцу важнее всего быстро находить дату), B не рекомендую.

## 3. Тап, заголовок, пустое состояние

**Тап.** Клетка дня в полотне — 8–12.4 pt, это ниже минимума 28 pt для элемента управления
(`accessibility.md`). Поэтому день в полотне **не является кнопкой**: тапается месяц, открывается
шит месяца с клетками 46 pt, тап по дню открывает карточку дня как вторую страницу того же шита
(с шевроном «‹ August»), а не второй шит поверх первого (`modality.md`: один шит за раз, очевидный
выход). Это ровно путь год → месяц → день в системном Календаре. Промах по соседнему месяцу
обратим одним «Done».

**Заголовок.** Название вкладки — Year, заголовок экрана — **2026** с шевроном выбора года
(pull-down в тулбаре, не вкладка: `tab-bars.md › Best practices` — вкладки навигируют, а не
действуют). У нового пользователя год один — шеврон не показывается.

**Итоги.** Строка под заголовком вида `148 days · 121 clean · 27 with corrections` (точные числа
считает генератор внутри файла: детерминированный год 2026, ~150 сыгранных дней из 272 прошедших,
плотность растёт к осени, есть отпускной провал 10–21 июля). **Серия не
показывается ни в каком виде** — это главный геймификационный приём (Duolingo), он превращает
пропущенный день в потерю и заводит счётчик, который надо беречь. Непрерывность и так видна на
полотне — это и есть весь смысл полотна. Числа даны нейтрально, без крупной цифры-героя и без
процентов.

**Пустое состояние.** Тот же холст, все месяцы на месте, но **ни один прошедший день не помечен
как пропуск** — нельзя пропустить день, когда тебя ещё не было. Нарисовано только кольцо сегодняшнего
дня + строка «Your year starts today. Each day you play leaves one mark here.» + кнопка «Open today's
puzzle» (`writing.md`: пустой экран приглашает к следующему шагу). В обычном состоянии то же правило
работает для начала января: аккаунт заведён 7 января, и 1–6 января не обвиняют пользователя.

## 4. Самокритика по линзам `apple-design`

Прошёл свой макет теми же линзами, что PD-7. Загруженные страницы: `accessibility.md`, `color.md`,
`typography.md`, `layout.md`, `dark-mode.md`, `tab-bars.md`, `motion.md`, `modality.md`,
`charting-data.md`, `writing.md`.

**Color (Lens 3).** Нашёл одно реальное столкновение значений и оставил его как открытый вопрос:
прозрачность чернил уже занята на карточке дня — там опорная шкала «Early → Late» кодирует **порядок
заполнения**. Если включить тон «с помощью» на полотне, светлые чернила в одном продукте будут
означать две разные вещи (рано заполнено / решено с помощью). Поэтому **тон по умолчанию выключен**,
и я рекомендую его не включать: в релизе 1 подсказок как функции вообще нет, а два оттенка одного
цвета в разных смыслах — ровно то, что запрещает `color.md`. Оставил переключателем, чтобы владелец
увидел оба.

**Accessibility (Lens 1).** Контур пропущенного дня — 1.71:1, ниже порога 3:1 для значащей графики.
Оставил сознательно: пропуск — это отсутствие значения, а не значение; он дополнительно читается по
положению относительно сегодняшнего дня и назван словами в итогах и в карточке дня. Кричать на
пользователя за пропуск было бы хуже, чем недотянуть контраст на элементе «ничего не было». В
`prefers-contrast: more` контур поднимается до 3.02:1. Клетки полотна помечены `aria-hidden`, а
озвучивается месяц целиком («August, 21 of 31 days solved, 4 with corrections») — VoiceOver получает
сводку, а не 365 безымянных квадратов; подробности по дню живут в шите, где каждый день — кнопка
46 pt с полной подписью. Размер клетки полотна привязан к ширине экрана (как сетка поля), всё
остальное масштабируется Dynamic Type до 200 %.

**Typography.** Никакой типографики «под бренд» тут нет и не должно быть: полотно — это график,
подписи месяцев 11 px (минимум iOS) Semibold, легенда 11 px, заголовок и кнопки — системные стили.
New York на этом экране не появляется вообще: сигнатура «дано серифом» принадлежит полю, тащить её
на график — декорация.

**Dark mode.** Метки пересчитаны именно над #1C1C1E, а не над #000 — иначе 62 %-й тон промахнулся бы
мимо 3:1. Никакого переключателя темы в продукте нет (`dark-mode.md › Best practices`), переключатель
в панели — только для ревью.

**Tab bars.** Таб-бар не тронут: те же три вкладки, то же стекло, те же фолбэки на
`prefers-reduced-transparency` / `prefers-contrast` / отсутствие `backdrop-filter`. Выбор года —
в тулбаре, не вкладкой.

**Motion.** На экране ровно одно движение — появление шита. Полотно **не** появляется волной по 365
клеткам: это было первое, что хотелось сделать, и это декорация, которая к тому же играла бы при
каждом открытии вкладки (`motion.md › Add motion purposefully`). При `prefers-reduced-motion` шит
не выезжает, а проявляется.

**Что убрал (обязательный пункт «remove one accessory»).**
1. Волну появления полотна (см. выше).
2. Мини-график «дни по месяцам» под полотном — полотно уже и есть этот график.
3. Счётчик серии и любые проценты — см. §3.
4. Тон «с помощью» из значений по умолчанию — см. Color.

**Чего проверить не могу.** `ui-serif` в Chromium даёт не New York (на этом экране серифа и нет —
проблема не возникает); срез угла на клетке 12.4 pt и различимость 62 %-го тона нужно смотреть на
реальном iPhone 16 — на скриншоте при 3× они читаются, на солнце и под углом может быть иначе.

## 5. Открытые вопросы владельцу

1. **Какая раскладка?** `C Blocks` (рекомендую — двенадцать боксов-месяцев, наследует поле) /
   `A Ledger` (12 строк, проще искать дату) / `B Ribbon` (сетка недель, похоже на GitHub).
2. **Исправления — цветом или тихо?** `Wax + nick` (день с исправлениями красный — прямо отвечает
   формуле «цвет по качеству», но год с плохим периодом выглядит красным) / `Nick only` (всё
   чернила, исправления только срезанным углом — спокойнее, но «цвета по качеству» фактически нет).
   Мой голос: `Wax + nick`, при условии, что исправления считаются по факту (были / не были), а не
   штрафуются количеством.
3. **Третий признак «решено с помощью» — нужен?** `Нет` (рекомендую: подсказок в релизе 1 нет, а
   светлые чернила уже значат «рано заполнено» на карточке дня) / `Да, включить тон 62 %` /
   `Да, но другим каналом` (тогда придётся придумать четвёртый канал — предложу).
4. **Пропущенный день — можно доигрывать?** В карточке пропущенного дня сейчас нарисована кнопка
   «Play this day's puzzle» (архив Sudoku.com по прошлым датам работает). `Да, доигрывать можно, и
   день перекрашивается` / `Да, но след в году остаётся пропуском` / `Нет, кнопки нет — день ушёл`.
   Это решение влияет и на движок, и на смысл всего полотна.
