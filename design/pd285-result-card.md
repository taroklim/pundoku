# PD-285: где на телефоне держать кнопки карточки «решено» в Play

Макет: `design/pd285-result-card.html` (самодостаточный). На десктопе это сетка вариантов «Сейчас / A / B / C» × 320 / 393 / 430
с панелью переключателей: тема, AX3, язык, тип партии (обычная / Лжец + подсказка / без повтора), Reduce Transparency,
положение прокрутки, масштаб. Каждая рамка прокручивается по-настоящему, а подпись под ней показывает замер: какие
кнопки видны целиком и сколько пикселей видно у остальных.

Кадры снимаются так (из `products/pundoku`):
`PD_PW_HOME=/Users/taroklim/Documents/KlymWork/gr487-w2/frontend node design/pd285-shots.mjs`. Результат появится в
`design/pd285-shots/`: chromium + webkit, @3x, около 80 кадров на браузер, `measure-cr.json` / `measure-wk.json` с замерами и
два обзора. **Кадры пока не сняты**: в этой сессии у дизайнера нет Bash. Скрипт сам проверяет вёрстку (`PD285.check()`,
подробности в шапке скрипта).

Вёрстку карточки я перенесла из `apps/web/src/styles/play.css`, `timelapse.css`, `shell.css` и `ResultCard.tsx`. Токены
взяты из `tokens.css`, новых цветов нет. Ревью вёл скилл `apple-design`: `tab-bars.md`, `toolbars.md`, `scroll-views.md`
(scroll edge effects), `layout.md`, `materials.md`, `accessibility.md`, `typography.md`.

## 1. Коротко

Рекомендую **вариант A, «Док действий»**. Карточка «решено» и так встаёт на место поля, а её кнопки встают на место пада:
«Watch your solve» (залитая) и под ней ряд «Share | New puzzle» прилипают к таб-бару. Карточка прокручивается под ними и
уходит под док через растушёвку 16 px. Высота дока около 120 px, почти как у пада с рядом действий во время партии
(122 px), поэтому после решения нижняя полоса экрана остаётся на месте, меняется только её содержимое. В покое все три
действия видны на 320, 393 и 430. Ничего не лежит под стеклом, и маска, которая гасит выглядывающую кнопку до 35 %, больше
не нужна. Док непрозрачный: стекло в продукте по-прежнему только у таб-бара. При AX3 и в ландшафте телефона дока нет,
кнопки остаются в конце карточки, как сейчас, потому что там док съел бы треть экрана.

## 2. Проблема (замер)

Замер `design/pd277-shots/fix-*.json` (PD-277, P): Play 393×852, 1rem = 17 px, safe-area 59/34. Верх таб-бара 754.

| Элемент | Покой: верх–низ | Видно над баром | Конец прокрутки |
|---|---|---|---|
| Watch your solve | 742–788 | **12 px**, и те под маской 35 % | целиком |
| Share | 796–842 | 0 | целиком |
| New puzzle | 846–894 | 0 (ниже бара и даже ниже экрана) | целиком, низ 694 |
| Прокрутка | 200 px (webkit) / 204 px (chromium) | | |

Почему так получается:
1. **Тепловая карта шириной во всю карточку**: 329 px на 393 и 366 px на 430. Она занимает почти половину экрана, а
   строки (Time, Fixes, Technique) и три кнопки остаются ниже.
2. **Три кнопки подряд в конце карточки**: 46 + 8 + 46 + 4 + 48 ≈ 152 px. Строка «Technique reached» на 393 и 430
   переносится («What's this?» не помещается в строку) и добавляет ещё около 20 px.
3. **Маска scroll-edge** (`play.css`, `.scroll:has(.card)`) приглушает до 35 % всё, что ниже `100% − 86 px − inset`. Край
   залитой кнопки, видный на 12 px, получается полупрозрачным под стеклом и выглядит как ошибка отрисовки, а не как
   «ниже есть ещё».
4. **320×568**: там уже действует уплотнение PD-87 (карта 128 px, строки 4 px), но по расчёту Watch помещается, Share
   выглядывает на несколько пикселей, а New puzzle лежит под баром. На **430×932**, по расчёту, Watch видна, Share
   срезана баром, New puzzle под ним. Точные цифры по 320 и 430 даст `measure-*.json`, это кадры `now-*-rest`.

В конце прокрутки всё доступно (правило peek PD-144 работает). Дефект только в состоянии покоя, но это первый кадр после
каждой решённой партии.

## 4. Варианты

### A — «Док действий над таб-баром», **рекомендую**

Схема покоя (393×852, обычный текст):

```
 ┌───────────────────────────┐  59  safe-area
 │ Play                    ⚙ │
 │ Easy · 4:12               │
 │ ┌───────────────────────┐ │ 136
 │ │ Solved                │ │
 │ │ Every cell shaded…    │ │
 │ │ [ тепловая карта 329 ]│ │ 206–535
 │ │ Early ▁▂▃▄▅▆▇ Late    │ │
 │ │ Time            4:12  │ │ ~612
 │ │ Fixes          clean  │ │ ← уходит под растушёвку
 ├─┴───────────────────────┴─┤ 634  верх дока (непрозрачный, фон экрана)
 │ [ ▷  Watch your solve   ] │      залитая, 46
 │ [ ⇪ Share ][ New puzzle ] │      тонированная | текстовая, 46
 ├───────────────────────────┤ 754  таб-бар (стекло)
 │  Today    Play     Year   │
 └───────────────────────────┘ 852
```

- **Геометрия**: `padding 10 16`, Watch на всю ширину, ниже сетка 2×1 с зазором 8. Итого 10 + 46 + 8 + 46 + 10 = **120 px**,
  а на 320×568 (PD-87) 8 + 44 + 8 + 44 + 8 = 112 px. Нижний край дока стоит на верхнем крае таб-бара (sticky,
  `bottom: 0` при `padding-bottom` прокрутки, равном таб-бару с inset, см. §6). В конце прокрутки док стоит на своём естественном месте под карточкой, на тех же координатах,
  поэтому не прыгает.
- **Отделение от контента**: над доком растушёвка 16 px (`transparent → var(--bg)`), тот же приём, что `.scroll-fade` в
  shell.css. Это scroll edge effect по `scroll-views.md`: он появляется только там, где контент уходит под плавающий слой.
  В конце прокрутки растушёвка ложится на пустое поле 16 px под карточкой и не видна. При Reduce Transparency, Increase
  Contrast и forced-colors растушёвки нет, вместо неё линия `--hairline` (в forced-colors — `CanvasText`).
- **Что видно в покое**: на 393 видны карта пути, легенда и строка Time (время дублирует и подпись «Easy · 4:12» под
  заголовком). Fixes и Technique открываются прокруткой примерно на 130 px. На 320×568 благодаря уплотнению PD-87 видно
  почти всё, кроме строки Technique.
- **Где дока нет** (кнопки в конце карточки, как сейчас): (1) **AX3 и крупнее** (`html[data-type="ax3"]`). Подписи по
  40 px переносятся в 2–3 строки, док вырос бы до 250+ px, а на 320×568 это половина экрана. При таком размере текста
  всё равно читают прокруткой. (2) **Ландшафт телефона** (`(orientation: landscape) and (max-height: 500px)`, условие
  landscape.css). (3) Десктоп C. В этих случаях маска 35 % остаётся.
- **Сильное**: решает дефект на всех ширинах при обычном и крупном (до xxxL/AX2) тексте и при любом составе карточки
  (Лжец, подсказки, Чернила). Высота дока не зависит от длины карточки. Это знакомый iOS-паттерн «аксессуар над таб-баром»
  (`tab-bars.md`: MiniPlayer у Music) без нарушения правила «действия — не в таб-баре». Кнопки сразу под большим пальцем.
- **Слабое**: в покое док закрывает около 120 px карточки, и строки Fixes/Technique видны только после прокрутки. Новый
  элемент раскладки: условия «где дока нет» нужно держать в коде и тестах. При AX1–AX2 на 320×568 док выходит
  примерно 170–200 px (см. §8, риск 1).

**Развилка A — док в один ряд** (переключатель «Док A: 1 ряд + шапка», кадры `A1-*`). В доке «Watch your solve» и
квадратная кнопка Share со значком (46×46, `aria-label`), высота 66 px, ровно как у ряда Notes/Undo/Erase во время партии.
New puzzle переезжает в шапку текстовой кнопкой справа от заголовка; прецедент — PD-139, когда «New puzzle» уже была в
шапке. Плюс: на 54 px больше карточки в покое. Минусы: Share без подписи (общепринятый значок iOS, но всё равно значок).
Шапка решённой партии снова несёт действие, а PD-144 решил «на решённой партии шапка действий не несёт». Тест PD-129
«Share ниже Watch» придётся переписать. По умолчанию **2 ряда**, на это и рекомендация.

### B — «Плотная карточка»

Ничего не прилипает. Share и New puzzle встают в один ряд (экономия около 52 px), а тепловая карта уменьшается ровно
настолько, чтобы низ карточки оказался на 8 px выше таб-бара, но не меньше 144 px (на 320×568 — 112 px). Это развитие
приёма PD-87 и ландшафта PD-249, где «карта не выше видимой области». Подгонку по замеру делает JS, как `melody/hintFit.ts`
(PD-206): CSS не знает высоту строк Лжеца, переносы uk/ru и Dynamic Type. Если не помещается даже с минимумом, карта
возвращается к полному размеру и карточка прокручивается, как сейчас (подпись «не влезло»).
- **Сильное**: один экран без прокрутки, никаких закреплённых слоёв, на 393/430 с обычной партией влезает.
- **Слабое**: на 393 карта ужимается примерно с 329 до ~218 px (на треть), а это главный образ карточки. На 320×568 по
  расчёту не влезает (нужна карта меньше 100 px). Не влезает и при AX, и у Лжеца с подсказками на 393. Значит, дефект
  остаётся там, где хуже всего. Поведение зависит от содержимого: две разные партии дают два разных размера карты.

### C — «Действия над картой»

Порядок карточки меняется: «Solved» → Watch your solve → ряд Share | New puzzle → разделитель → подпись «Every cell
shaded…» → карта пути → легенда → строки. Время и сложность и так стоят в подписи под заголовком «Play».
- **Сильное**: действия на первом экране на любой ширине и при любом составе карточки (на AX3 по расчёту тоже, кроме
  New puzzle на 320). Без новых слоёв и без JS, меньше всего кода.
- **Слабое**: ломается порядок «результат → осмысление → действие». Первое, что видно после решения, — кнопки, а не
  картина собственного пути (ради неё карточка и задумана, PD-75/129). Карточка Play расходится с карточкой Today/архива,
  где кнопки внизу. Переносить C и туда — это пересмотр утверждённого Today, вне этого тикета. Карта пути и строки
  в покое срезаны снизу, то есть дефект переезжает с кнопок на данные.

## 5. Рекомендация и обоснование

**A, док в 2 ряда.**
1. **Действие всегда там, где палец.** Во время партии нижняя полоса над таб-баром — пад и действия. После решения в этой
   же полосе стоят «что дальше» (посмотреть / поделиться / новая сетка). Пространственная память не ломается, и
   «New puzzle» больше не нужно искать прокруткой.
2. **Таб-бар — для навигации, действия — над ним, а не под ним** (`tab-bars.md`: «Use a tab bar to support navigation,
   not to provide actions»). Сейчас при тапе в низ экрана вместо «New puzzle» срабатывает вкладка Play (PD-256: «тап
   уходит во вкладку Play»). В A это невозможно: док и таб-бар не перекрываются.
3. **Прокрутка остаётся честной** (`scroll-views.md`: «Make it apparent when content is scrollable… partial content at
   the edge»). Под доком уходит контент (строки), а не кнопка, и растушёвка здесь работает как scroll edge effect у
   плавающего слоя. Сейчас под маской гаснет как раз кнопка, отсюда и вид «обрезана».
4. **Карта пути не страдает** (в отличие от B), а **порядок чтения карточки сохраняется** (в отличие от C).

Что спорно: (а) 120 px дока в покое закрывают строки Fixes/Technique (компромисс ради кнопок, см. развилку «1 ряд»);
(б) отказ от дока при AX3. Альтернатива — док из одной Watch при AX3, но тогда кнопки разъедутся по двум местам, и я
считаю это хуже.

## 6. Спека для разработчика (вариант A)

**Где включается** (`dockOn`): Play, `cardView && !desk`, и `html:not([data-type="ax3"])`, и НЕ
`(orientation: landscape) and (max-height: 500px)`. Today, архив, Year — никогда. Условие лучше держать в одном хуке
(`useResultDock`), который читает `matchMedia` и атрибут `data-type`, плюс один класс на корне экрана, чтобы CSS и тесты
смотрели в одно место. При смене ориентации или размера текста кнопки переезжают между доком и карточкой без
перезагрузки.

**DOM.** Кнопки рендерит `ResultCard`, как сейчас: `useTimelapseEntry`, шиты, `openTl` остаются там. При `dockOn` они
порталом (`createPortal`) уходят в `div.result-dock[role="group"][aria-label=<заголовок карточки>]`, который `PlayScreen`
ставит последним ребёнком `.play` сразу после `section.card`. Копия одна, testid прежние, порядок DOM: карточка → док.
Фокус после решения, как сейчас, на карточке (`cardRef`). Таб вперёд с последней строки ведёт в Watch.

**CSS** (play.css, рядом с «Карточка решено»; значения из макета):

```css
.scroll:has(.result-dock) {                  /* док сам отделяет контент: без запаса 16 px и без маски 35 % */
  padding-bottom: calc(var(--tabbar-h) + var(--sa-bot));
  -webkit-mask-image: none;
  mask-image: none;
}
.play:has(.result-dock) { padding-bottom: 0; }
.play:has(.result-dock) > .card { margin-bottom: 16px; }   /* растушёвка в конце прокрутки ложится на пустой фон */
.result-dock {
  position: sticky;
  bottom: 0;                                   /* НЕ tabbar-h + sa-bot: sticky отсчитывается от края прокрутки за вычетом
                                                  padding .scroll, а он уже равен таб-бару + inset (иначе отступ дважды) */
  z-index: 2;                                  /* ниже таб-бара (20) и тостов (30) */
  margin-top: auto;                            /* короткая карточка: док всё равно у таб-бара */
  flex: none;
  background: var(--bg);
  padding: 10px max(16px, var(--sa-r)) 10px max(16px, var(--sa-l));
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);
  gap: 8px;
  animation: fadeIn calc(200ms * var(--mk)) var(--e-out) both;
}
.result-dock::before {                         /* scroll edge 16 px */
  content: ""; position: absolute; left: 0; right: 0; bottom: 100%; height: 16px;
  pointer-events: none; background: linear-gradient(to bottom, transparent, var(--bg));
}
.result-dock > * { margin: 0; }
.result-dock .tl-watch, .result-dock .tl-nolog { grid-column: 1 / -1; }
.result-dock .newgrid {
  min-height: 46px; border-radius: 11px; padding: 8px 12px; font-size: 0.95rem;
  display: flex; align-items: center; justify-content: center;
}
.result-dock .newgrid:only-child { grid-column: 1 / -1; background: var(--ink-tint); font-weight: 600; }  /* §3 п. 2 */
@media (prefers-reduced-transparency: reduce), (prefers-contrast: more) {
  .result-dock::before { display: none; }
  .result-dock { box-shadow: 0 -1px 0 var(--hairline); }
}
@media (forced-colors: active) {
  .result-dock::before { display: none; }
  .result-dock { border-top: 1px solid CanvasText; }
}
@media (max-height: 600px) and (max-width: 430px) {      /* PD-87 */
  .result-dock { padding-block: 8px; }
  .result-dock > * { min-height: 44px; }
}
```

Строка «повтор недоступен» (`tl-nolog`) — это пояснение, а не действие. Она остаётся **в карточке** (в макете так и
сделано), в доке тогда только New puzzle (`:only-child`). Правило `.result-dock .tl-nolog` в CSS выше — страховка на случай,
если при реализации окажется проще портировать `WatchRow` целиком. Тогда строка займёт ряд дока, и это тоже допустимо.

## 8. Риски и решения, принятые по умолчанию (к владельцу не выносятся)

1. **AX1–AX2 на 320×568**: док примерно 170–200 px из 504 над таб-баром. Если на iPhone SE с крупным текстом карточке
   станет тесно, порог дока сдвигается с AX3 на «1rem ≥ 28 px» (тот же зонд `dynamicType.ts`, второй атрибут). На
   iPhone 16 владельца не проявляется.
2. **Растушёвка в тёмной теме**: `transparent → #000` поверх карточки `#1C1C1E`. Это мягкий переход в чёрный, проверить
   на OLED: кадры `A-393-dark-mid`, `A-320-dark-mid`.
3. **Sticky в WebKit/iOS** внутри `.tab-pane` при слайде вкладок PD-161: на панелях в покое нет transform (shell.css),
   sticky считается от прокрутки панели. Нужен живой тест перехода Play → Today → Play на решённой карточке.
4. **Маска 35 %** без дока остаётся (AX3, ландшафт). Убирать ли её вовсе — отдельный вопрос, к PD-285 не относится.
