Решение владельца 2026-10-04: переключение Today · Play · Year — **слайд** (заменяет «кроссфейд
без свайпа» от 2026-10-01, PD-81 §8 вопрос 2). **Свайп-жеста нет** — анимация только по тапу в
таб-баре (и по стрелкам/Home/End в tablist для клавиатуры). Это макет на выбор, реализации нет.

## 1. Общее для всех трёх вариантов

| Вопрос | Решение (одно для A/B/C) |
| --- | --- |
| Направление | **По порядку вкладок, а не по нажатой клавише.** Вкладка правее (Today→Play, Play→Year, Today→Year) — новый экран приходит справа, старый уходит влево. Левее — зеркально. Стрелка → на Year (wrap на Today) тоже ведёт влево: порядок важнее клавиши. |
| Прыжок через одну (Today↔Year) | **Напрямую**: Year приходит сразу за Today, Play не показывается, длительность та же. Для A в макете есть альтернатива «через Play» (лента едет на 2 ширины) — для сравнения, не рекомендую: на 300 мс показывается экран, которого не просили, и скорость удваивается. |
| Обратная связь на тап | **Мгновенно**: цвет и жирность подписи вкладки меняются в момент тапа (как сейчас, 120 мс linear), не ждут конца слайда. |
| Таб-бар | **Стоит.** Выбранная вкладка показывается отдельной пилюлей (тот же `--ink-tint`, радиус 14), пилюля **переезжает** transform'ом той же длительностью и кривой, что экран. Сейчас фон рисует сам `.tab[aria-selected]` — его заменяет пилюля. В `forced-colors` пилюля скрыта, остаётся рамка `Highlight` (как сейчас). |
| Шапка экрана | **Едет вместе с контентом** во всех вариантах. Шапка (`.toolbar` + `.subline`) — часть каждого экрана в коде (`TodayScreen`, `PlayScreen`, `YearTab`), у вкладок разные заголовки и разные кнопки справа; «стоящая» шапка с кроссфейдом заголовка потребовала бы общего слоя шапки в оболочке — это рефакторинг всех трёх экранов ради эффекта, который в варианте C и так почти незаметен. Шестерёнка на всех вкладках в одной точке — в A/B она уезжает и тут же приезжает на то же место; это честно отражает «другой экран». |
| Прерывание новым тапом | **Подхват с текущего места.** Новый тап читает текущее положение каждого видимого экрана и пилюли (computed transform/opacity), отменяет анимации и запускает новые **от этого положения** к новой цели. Без рывка в конец, без очереди, ввод не блокируется никогда. Тап по вкладке, к которой уже едем, — игнорируется. Демо «Прерывание» и «Серия тапов». |
| Повторный тап по своей вкладке | Не переход. Существующее поведение PD-144 (Play → хаб) не меняется. |
| Settings / Help / архив дня | **Вне тикета.** Это экраны поверх вкладки (push), их вход/выход остаётся как есть (M10 fadeRise 200 мс). Тап по вкладке из Settings идёт через `recoveryStore.requestLeave` — слайд начинается **после** того, как guard разрешил уход. Направление в этом случае — от вкладки-источника Settings (`origin`) к цели; если цель = источник, это «назад», не слайд. |

## 2. Вариант A — «Лента» (рекомендация)

> Три экрана лежат в ряд Today · Play · Year; тап сдвигает ленту.

| Параметр | Значение |
| --- | --- |
| Движение | Оба экрана сдвигаются на **полную ширину**, 1:1, как одна жёсткая лента. Без затухания. |
| Длительность / кривая | **300 мс**, `cubic-bezier(0.32, 0.72, 0, 1)` (= `--e-ring`, замедление в стиле iOS, без перелёта). |
| Пружина? | Нет. Перелёт на полной ширине открывает край соседнего экрана/фон на 1–2 кадра — читается как дефект. Если захочется «живее» — не bounce, а чуть короче (260 мс). |
| Прыжок Today↔Year | Напрямую, 300 мс (альтернатива «через Play» есть в макете). |
| Пилюля | Переезжает 300 мс той же кривой (через одну — две ячейки за то же время). |
| Шапка | Едет с экраном. |
| Reduce Motion | Кроссфейд 200 мс (§5). |

**Цена:** средняя — общий движок (§4) плюс функция «где лежит экран вне кадра» на 1 строку.

## 3. Вариант B — «Push с параллаксом»

> Как навигационный push iOS: правый по порядку экран лежит **сверху**.

| Параметр | Значение |
| --- | --- |
| Движение | Вперёд: входящий наезжает справа на всю ширину **поверх**; нижний уходит влево только на **30 %** и гаснет до **opacity .55**. Назад: верхний съезжает вправо целиком, нижний возвращается с −30 % и проявляется. |
| Длительность / кривая | **350 мс**, `cubic-bezier(0.32, 0.72, 0, 1)`. |
| Тень | Левый край верхнего экрана: `-10px 0 28px rgba(0,0,0,.10)` — только светлая тема; в тёмной `none` (тень на #000 не видна, отделяет затухание нижнего). Тень рисуется в слое экрана, перерисовки не требует. |
| Порядок слоёв | `z-index` = индекс вкладки на время перехода, снимается в конце. |
| Прыжок Today↔Year | Напрямую: Year наезжает на Today. |
| Пилюля / шапка | Пилюля 350 мс; шапка едет с экраном. |
| Reduce Motion | Кроссфейд 200 мс. |

**Против (почему не рекомендую):** это движение «провалиться на уровень глубже». В Pundoku им
(в прямом или упрощённом виде) уже открываются Settings, справка и архив дня с «‹ Year» — тапнув
вкладку, человек увидит тот же жест, что и при входе в настройки, и иерархия «вкладки — равные,
push — вглубь» размывается. Плюс самый длинный (350 мс) на самом частом действии.

## 4. Вариант C — «Сдвиг» (shared axis)

> Направление показано коротким сдвигом, смена — кроссфейдом.

| Параметр | Значение |
| --- | --- |
| Движение | Оба экрана смещаются на **32 px** в сторону хода и кроссфейдятся. Уходящий гаснет к **55 %** времени, входящий проявляется с **25 %** — без «двойной экспозиции» в середине. |
| Длительность / кривая | **240 мс**, `cubic-bezier(0.2, 0.7, 0.3, 1)` (= `--e-out`). |
| Прыжок Today↔Year | Смещение **48 px** вместо 32 («дальше»), время то же. |
| Пилюля / шапка | Пилюля 240 мс; шапка едет с экраном, на 32 px это читается как смена заголовка. |
| Reduce Motion | Кроссфейд 200 мс (просто без сдвига). |

**Плюс:** самый короткий и лёгкий, меньше всех «обещает свайп». **Минус:** это ближе всего к
кроссфейду, от которого владелец только что отказался, — велик шанс услышать «а где слайд».
Держу его как **запасной** к A (§8).

## 5. Reduce Motion и Reduce Transparency

**Reduce Motion — рекомендую кроссфейд 200 мс, не мгновенную смену.** Для всех вариантов одно и
то же: сдвиг = 0, экраны меняются прозрачностью, пилюля встаёт на место **мгновенно** (без
переезда). Почему не мгновенно: (1) HIG `motion.md` для Reduce Motion предлагает заменять
движение растворением, а не убирать переход; (2) 200 мс — ровно нынешний M10, ощущение владельцу
знакомо; (3) Today (светлые карточки) → Year (поле цветных квадратов) мгновенной сменой даёт
вспышку. Если владелец захочет «вообще ничего» — это одна константа.

Реализация в духе PD-89 («единственное место, где читается prefers-reduced-motion — `--mo` на
`:root`»): движок перехода в JS **не вызывает `matchMedia` сам**, а читает
`getComputedStyle(document.documentElement).getPropertyValue('--mo')`: `0` → кроссфейд-спека,
`1` → спека варианта. Так источник правды остаётся один. (`--mk` здесь не используется: вариант A
не имеет прозрачности, и `--mo` не может сам превратить слайд в растворение — нужна отдельная
спека, а не множитель.)

**Reduce Transparency не ломается:** анимация не трогает таб-бар, кроме пилюли. При Reduce
Transparency / `prefers-contrast: more` / без `backdrop-filter` таб-бар уже непрозрачный
(`--glass-solid`) — правила `shell.css` не меняются. Пилюля — это `--ink-tint`, она одинакова на
стекле и на заливке. Кадры `rt-*` в скрипте это показывают посреди перехода.

## 6. Требования к разработке

### 6.1 Экраны не размонтируются (главное изменение)

Сейчас `App.tsx` рендерит **одну** панель с `key={panelKey}` — при смене вкладки экран
размонтируется. Партия при этом живёт в сторах (`playStore`, `dayStore`), но теряются прокрутка,
локальный `useState` (выбор клетки, раскрытые блоки) и любая анимация на полпути. Для слайда
нужны **оба** экрана одновременно, поэтому:

1. Три панели вкладок (`panel-today`, `panel-play`, `panel-year`) **смонтированы всегда** после
   первого посещения (ленивый первый маунт допустим: вкладка, которую ещё не открывали, может не
   рендериться до первого тапа — но после этого больше не размонтируется).
2. Неактивная панель: `visibility: hidden` + `inert` + `aria-hidden="true"`. **Не `display:none`**
   (сбрасывает `scrollTop` и раскладку) и **не** условный рендер.
3. **У каждой панели свой скролл-контейнер.** Сейчас скроллится общий `.scroll`, а правило
   `.scroll:has(.play-fit, .play-hub)` переключает ему `overflow` — при трёх смонтированных
   панелях `:has()` будет срабатывать всегда. Перенести `overflow-y:auto`, peek-отступ
   `padding-bottom: calc(16px + var(--tabbar-h) + var(--sa-bot))` и исключение для Play внутрь
   каждой панели. Позиция прокрутки Today/Year сохраняется автоматически (DOM не трогается).
4. **Сигнал «вкладка активна»** каждому экрану (проп `active` или контекст). Раньше «неактивен» =
   «размонтирован», и всё, что живёт в эффектах, останавливалось само. Теперь обязательно:
   таймер партии на Play **стоит**, пока Play не активна (сейчас пауза, видимо, наступает при
   размонтировании — проверить); `useSolveSequence`/финал на Today не стартует в скрытой
   панели; Year не потребляет `initialDate`, пока не активен; автофокус/`scrollIntoView` — только
   у активной. В макете таймер Play это и показывает.
5. Settings / Help / архив остаются отдельным уровнем поверх (как сейчас, с `key` и fadeRise),
   но **не размонтируют** панели вкладок под собой — иначе при «‹ назад» состояние снова
   потеряется. Самое простое: рендерить их поверх стопки вкладок, а стопку прятать `inert`.
6. `ErrorBoundary scope="tab"` — по одной на панель (сейчас сбрасывается сменой `key`; теперь
   экран сбоя вкладки должен сбрасываться явно при уходе с неё, PD-146).

### 6.2 Никаких transform после конца перехода

Во всём `apps/web/src/styles` есть 7 элементов с `position: fixed` внутри экранов (шиты Today,
хаба Play, Year, Settings, таймлапс, чернильный режим). Любой `transform` **или
`will-change: transform`** на предке делает его containing block для `fixed` — шит
прилипает к панели вместо экрана (именно поэтому нынешний M10 стоит на `fill-mode: backwards`).
Поэтому:

- `will-change: transform, opacity` ставится на две панели **в начале** перехода и снимается в
  конце; в покое его нет;
- после конца анимации на панелях **нет inline transform/opacity** — не `translateX(0)`, а ничего
  (в макете: `animation.cancel()` после `finished`; **не** `commitStyles()`, он оставляет inline);
- шит, открытый в момент тапа по вкладке: проверить, что скрим шита перекрывает таб-бар (тогда
  переход невозможен). Если где-то таб-бар доступен при открытом шите — шит обязан либо
  закрываться до слайда, либо рендериться порталом в `.shell`/`body`. Предпочтительно —
  порталы для всех `fixed`-шитов: это снимает риск целиком.
- Скрипт кадров проверяет это автоматически (`computed transform === "none"` после `finish`).

### 6.3 Движок перехода

- **Web Animations API** (`element.animate`), не CSS-классы: CSS-анимацию нельзя подхватить с
  текущего места при прерывании. Псевдокод — функция `go(to)` в макете (≈40 строк): снимок
  текущих положений → `cancel()` → новые анимации от снимка → по `finished` (с проверкой токена
  перехода) — спрятать неактивные, снять `will-change`, `cancel()`.
- Только `transform: translateX()` и `opacity`. Без `left`, `width`, `filter`, `box-shadow`-анимаций.
- Пилюля — отдельный `span` в `.tabbar`, ширина/высота/позиция берутся из первой вкладки и
  пересчитываются на `resize` и при смене Dynamic Type (подпись вкладки меняет высоту бара,
  `--tabbar-h` 64→67).
- Тесты: `App.motion.test.tsx` сейчас проверяет класс `.panel.enter` и единственный `[role=tabpanel]` — его придётся
  переписать на новый движок (в jsdom WAAPI нет: замокать `animate` или проверять конечное
  состояние).
- Фокус: стрелки в tablist по-прежнему двигают фокус на вкладку (`TabBar.tsx`), фокус в панель не
  переносится. VoiceOver: у неактивных панелей `aria-hidden` + `inert` — в ротор не попадают.

## 7. Производительность (iPhone 16, A18)

- **Анимируются только `transform` и `opacity`** — в WebKit это композитные анимации Core
  Animation: layout и paint во время перехода не происходят. 60 fps — **да**, с запасом. iOS
  Safari/PWA по умолчанию рендерит страницы около 60 Гц (флаг «Prefer Page Rendering Updates near
  60fps» включён), 120 Гц ProMotion веб-контенту обычно не достаётся — тайминги считать под 60.
- **Память слоёв:** экран 390×844 pt @3x ≈ 1170×2532 px ≈ 11,9 МБ текстуры. Переход = 2 слоя
  ≈ 24 МБ (A «через Play» — 3 слоя ≈ 36 МБ) на 300 мс. Для A18 не нагрузка.
- **Самая дорогая операция кадра — стекло таб-бара:** `backdrop-filter: blur(24px)` над
  движущимся контентом пересчитывается каждый кадр, но только в полосе бара (~390×104 pt). Ожидаю
  без потерь; при Reduce Transparency её нет вовсе. Проверить на устройстве в варианте A — это
  худший случай (под баром за 300 мс проходит вся ширина двух экранов).
- **Риск первого кадра:** скрытая `visibility:hidden` панель разложена, но не нарисована. В момент
  показа её надо нарисовать (Year — 365 квадратов, Play — поле), это может съесть первый кадр
  перехода. Митигация: снять `visibility` и стартовать анимацию в следующем `requestAnimationFrame`
  (задержка 16 мс невидима — цвет вкладки уже сменился мгновенно). Если на устройстве всё равно
  дёргается первый кадр — держать соседние панели нарисованными (`opacity:0` вне кадра) ценой
  памяти, но сначала измерить.
- Ни одной зацикленной анимации, ни одного `will-change` в покое — на батарею не влияет.

## 8. Рекомендация PM'у

**Вариант A «Лента»: 300 мс, `cubic-bezier(0.32, 0.72, 0, 1)`, прыжок через одну — напрямую,
шапка едет с экраном, пилюля переезжает, прерывание — подхват с текущего места; Reduce Motion —
кроссфейд 200 мс.**

1. **Это ровно то, что попросил владелец.** Он отказался от кроссфейда в пользу слайда; A — слайд
   в чистом виде, где видно, что Today · Play · Year лежат в ряд в том же порядке, что и в
   таб-баре. C слишком похож на отклонённый кроссфейд.
2. **Равные вкладки двигаются как равные.** Оба экрана едут одинаково — «соседи по ленте».
   B — push, то есть «вглубь», и путается с настоящими push'ами Pundoku (Settings, справка, архив).
3. **Частое действие остаётся быстрым.** HIG `motion.md` предостерегает от движения на частых
   взаимодействиях; 300 мс без перелёта, мгновенный отклик таб-бара и **никогда не
   блокируемый ввод** (подхват при прерывании) делают слайд не тормозом, а подтверждением.
4. **Цена A = цена C.** Движок один (§6.3), различаются одна функция «где экран вне кадра» и две
   константы. Главная стоимость тикета — не анимация, а §6.1 (держать экраны смонтированными) и
   §6.2 (fixed-шиты), и она одинакова для всех трёх.

**Запасной ход:** если на iPhone A покажется тяжёлым для частого Today↔Play — переключить на C
(та же реализация, менять `off()` и `240 мс / --e-out`). Решать по устройству, не по макету.

процитированным в прежних макетах: принципы → линзы → «убрать один аксессуар».

- **[High, учтено] Слайд обещает свайп.** Владелец принял это осознанно. Смягчение — в A нет
  перелёта и нет «резинки», а значит нет физики, которая звала бы потянуть пальцем; в C обещание
  ещё слабее. Edge-swipe iOS (назад по истории) — системный и с вкладками не связан, мы его не
  трогаем (`useRoute` уже ловит `popstate`).
- **[High, учтено] Ввод не блокируется анимацией** (HIG: интерфейс отзывчив во время движения) —
  подхват с текущего места, демо «Серия тапов».
- **[Medium, учтено] Reduce Motion** — замена растворением, а не отключение перехода (§5).
- **[Medium, учтено] Демо макета не перекрывают экран.** Панель макета — сбоку рамки (≥ 440 px)
  или под ней (телефон); на телефоне вариант A/B/C переключается мини-кнопками в зоне
  статус-бара, а таб-бар в рамке живой. Ряд демо **переносится**, а не скроллится вбок
  (замечание PD-81).
- **[Low] «Убрать один аксессуар»:** тень верхнего экрана в B. Без неё B в светлой теме читается
  хуже, поэтому оставлена — ещё один довод в пользу A, где аксессуаров нет вовсе.
- **Оценка:** A — *Good*, C — *Good*, B — *Needs decision* (корректен по HIG, но смешивает
  семантику вкладок и push).

**Не могу проверить:** ощущение 300 мс на устройстве; первый кадр Year на настоящем iPhone (§7);
`ui-serif` → New York (в Chromium засечки фолбэчные).
