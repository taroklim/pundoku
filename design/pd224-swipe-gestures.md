# Часть A. Свайп-удаление строки режима с незаконченной партией

## A1. Одним абзацем

На хабе Play строка режима, у которой есть незаконченная партия («● Не закончена · Сложно · осталось 47 · 03:18»),
тянется **справа налево**. Короткий свайп оставляет строку **открытой** с красной кнопкой **«Удалить»** справа;
свайп за порог (≈55 % ширины строки) — кнопка заливает всю строку, отпускание **удаляет**. Строка при этом не
исчезает (режим вечен): её содержимое возвращается на место, статус сменяется описанием режима. Внизу на 6 с —
тост **«Сетка „Лжец“ удалена · Отменить»** (рекомендую и даю как дефолт; альтернатива «подтверждение» — §A7.2,
вопрос владельцу). Без жеста то же делает пункт **«Удалить сетку»** в контекстном меню строки (долгое нажатие,
уже есть — ModeMenu) и отдельная кнопка «Удалить незаконченную сетку: Лжец» для клавиатуры и VoiceOver.

## A2. Что свайпается, а что нет

| Строка | Свайп | Почему |
|---|---|---|
| Строка режима **с** незаконченной партией (`slots[mode]` есть) | **да** | Это и есть «старая партия» |
| Строка режима **без** партии (описание) | нет, строка не двигается вовсе | Удалять нечего; «пустой» ход строки обещал бы действие |
| «Продолжить → Головоломка дня», «Лжец дня» | **нет** | Партии дня — история и Year, сервер — источник правды; это другое действие с другими последствиями (вопрос владельцу §A12, дефолт «нет») |
| Шиты, меню, Today, Year | нет | Вне тикета |

## A3. Анатомия и параметры

```
 .srow  (обёртка, НЕ движется; ей принадлежит разделитель-hairline)
 ├── button.hub-row.mode.fg   ← существующая строка; единственный движущийся слой, translateX(x), фон --card (непрозрачный)
 └── button.del               ← под строкой, прижата вправо, на всю высоту строки; ширина = max(A, −x)
      └── .dlw (A px)         ← подпись «Удалить» по центру правых A px; в состоянии «armed» уезжает к левому краю красного
```

DOM-порядок: сначала строка, потом кнопка (порядок Tab и VoiceOver: «Лжец, не закончена…» → «Удалить незаконченную
сетку: Лжец»). Карточка уже `overflow:hidden; border-radius:12px` — красный в первой/последней строке скругляется сам.

**Обозначения:** `W` — ширина строки (= карточки): 288 px на 320, 358 на 390, 398 на 430. `x` — сдвиг строки (≤ 0).

| Параметр | Значение | Комментарий |
|---|---|---|
| Порог распознавания (slop) | **10 px** | = `MOVE_SLOP_PX` долгого нажатия; до него жест не решён |
| Угол | захват, если `|dx| ≥ 10` **и** `|dx| ≥ 1,5·|dy|` (≤ ~34° от горизонтали) | Если раньше набралось `|dy| ≥ 10` при более крутом угле — жест отдаётся прокрутке до конца касания |
| Направление | только справа налево с закрытой строки; слева направо — только у открытой (закрыть) | Слева направо на закрытой — ничего, строка не двигается |
| Мёртвые полосы | касание, начатое ≤ 16 px от левого/правого края экрана, свайп не начинает | Сейчас там поле карточки (16 px) — правило на будущее (ландшафт, жест «назад» из части B) |
| Ширина кнопки `A` | `max(80, ширина подписи + 32)` px | ≈ en 86, ru 96, uk 104 при обычном тексте |
| Режим «значок» | если `подпись + 32 > 0,45·W` → только значок корзины (28–30 px), `A = 88`; подпись — a11y-имя | Срабатывает при AX-размерах (320 AX3 — во всех языках; 390 AX3 — uk/ru) |
| Остаётся открытой | отпустили при `−x ≥ A/2` | Иначе закрывается |
| Бросок | скорость по последним 100 мс: `≤ −0,3 px/мс` при `−x ≥ 16` → открыть; `≥ +0,3` → закрыть | Как `FLICK` у `useSheetSwipe`, но мягче (строка короче шита). **Бросок никогда не удаляет** |
| Порог полного свайпа `T` | `max(0,55·W, A + 72)` px | 320: en 158 / ru 168 / uk 176; 390: 197; 430: 219. При AX3 растёт с `A`, но всегда `< W` |
| Гистерезис | «armed» гаснет при `−x < T − 24` | Палец, вернувшийся чуть назад, не мигает состоянием |
| Предел | `x ≥ −W` (строка уходит максимум целиком) | |
| Резинка | открытая строка, тянутая вправо за 0: `min(12, dx·0,2)` px | С закрытой — 0 |
| Мультитач | второй палец игнорируется, пока первый ведёт жест | |

**Решение по отпусканию** (вынести в чистую функцию для юнит-теста, как `shouldDismiss`):

```
armed:            v ≥ +0,3 → открыть (передумал броском) ; иначе → УДАЛИТЬ
не armed:         v ≥ +0,3 → закрыть
                  v ≤ −0,3 и −x ≥ 16 → открыть
                  −x ≥ A/2 → открыть ; иначе → закрыть
pointercancel:    никогда не удаляет: −x ≥ A/2 → открыть ; иначе → закрыть
```

**Длительности** (кривые — токены `tokens.css`):

| Переход | Длительность | Кривая | При Reduce Motion |
|---|---|---|---|
| Ведение пальцем | 1:1, без анимации | — | так же (прямое манипулирование — не анимация, как у `useSheetSwipe`) |
| Доводка в «открыта»/«закрыта» | 220 мс | `--e-spring` | 0 мс (мгновенно) |
| Подпись к левому краю при входе/выходе из armed | 140 мс | `--e-out` | 0 мс |
| Удаление: строка возвращается из `x` в 0 | 260 мс; красный слой снимается после окончания | `--e-spring` | 0 мс |
| Статус → описание в строке | прозрачность 160 мс × `--mk` | linear | 115 мс, только прозрачность |
| Тост: появление | 200 мс × `--mk`, `translateY(16px × --mo)` + прозрачность | `--e-out` | 144 мс, только прозрачность |
| Тост: уход | 160 мс × `--mk`, прозрачность | linear | 115 мс |

Все сдвиги домножаются на `--mo`, длительности прозрачности — на `--mk` (правило PD-89: отдельных фолбэков не писать).
Вибрации нет (роадмап: «НЕ делать вибрации»; в iOS-PWA и нельзя) — щелчок нативного iOS при «armed» заменён
видимым скачком подписи к левому краю.

## A4. Состояния

| Состояние | Вид | Вход | Выход |
|---|---|---|---|
| `closed` | обычная строка | — | палец ↓ на строке |
| `tracking` | без изменений; таймер долгого нажатия 500 мс идёт | pointerdown на строке с партией | slop по горизонтали → `dragging`; slop по вертикали → `closed` (прокрутка); 500 мс без сдвига → контекстное меню; отпускание → тап (открыть партию) |
| `dragging` | строка едет за пальцем, справа проступает красное «Удалить»; `:active`-подсветка строки снята | захват жеста | отпускание/cancel → правило выше |
| `armed` | красное на всю открытую ширину, подпись у левого края красного | `−x ≥ T` во время ведения | `−x < T − 24` → `dragging`; отпускание → удаление |
| `open` | строка сдвинута на `−A`, видна кнопка «Удалить» (цель ≥ 44×высота строки) | отпускание по правилу; фокус клавиатуры на кнопке | см. «Закрытие»; тап по кнопке → удаление |
| `committing` | строка возвращается в 0, статус → описание; затем тост | удаление | конец анимации → `closed` (строка уже без партии и не свайпается) |

**Одна открытая строка на экран.** Начало свайпа другой строки закрывает открытую.

**Закрытие открытой строки** (доводка 220 мс):
- тап в любом месте хаба вне кнопки «Удалить» — **тап поглощается** (ничего не открывает; как в iOS);
- тап по самой открытой строке — закрывает, партию не открывает;
- свайп открытой строки вправо;
- прокрутка хаба больше чем на 4 px;
- тап по таб-бару или шестерёнке — строка закрывается мгновенно, **а тап проходит** (переход выполняется);
- повторный тап по вкладке Play (reselect), уход с вкладки, `visibilitychange: hidden` — мгновенно;
- Esc (клавиатура), открытие любого меню/шита.

Касание, сдвинувшееся больше slop (10 px) в любом направлении, **никогда** не становится тапом по строке (на тач
браузер сам не даёт click после панорамы; для мыши — подавлять в коде, как `suppressClick` у `useSheetSwipe`).

## A5. Арбитраж с другими жестами

| С чем | Как разводим |
|---|---|
| Вертикальная прокрутка хаба | `touch-action: pan-y` на строке: вертикаль браузер ведёт сам и шлёт `pointercancel`, горизонталь приходит в JS. Плюс угол 1,5:1 и slop 10 px. `.hub-scroll { overflow-x: hidden }` — сдвинутая строка не должна дать горизонтальную прокрутку |
| Долгое нажатие (ModeMenu, 500 мс) | Тот же slop 10 px: сдвиг > 10 px отменяет таймер; сработавшее меню отменяет свайп. У открытой строки долгое нажатие не запускается (касание её закрывает/ведёт) |
| Жест «назад» от левого края | В standalone-PWA системного «назад» нет (проверить на iPhone, §A11 п. 4); в Safari-вкладке он есть, но идёт **слева направо от края**, наш — справа налево и начинается в строке (≥ 16 px от края). Пересечения нет. Мёртвые полосы 16 px — запас на будущий свой жест «назад» (часть B) |
| «Вперёд» от правого края (только Safari-вкладка) | Строка кончается в 16 px от края; касания в полосе 16 px свайп не начинают |
| Нижний край (home indicator) / Центр уведомлений / Пункт управления | Хаб выше таб-бара; системные жесты по краям приоритетнее и нам не мешают |
| Жесты поля (выбор клетки, осмотр Фонаря 0,45 с, обвинение Лжеца 0,5 с) | Не пересекаются: свайп живёт только на строках хаба, поля на хабе нет |
| PD-214 (без выделения при удержании) | Уже на `.hub-row.mode` (`-webkit-touch-callout:none; user-select:none`) — сохранить на движущемся слое |
| Шит «Стянуть вниз» (`useSheetSwipe`) | Пока открыт шит, хаб под затемнением — свайп строк не работает |

## A6. Что удаляется

- **Локально:** слот режима `meta:playGame:<mode>` в IndexedDB → `null` (тот же путь, что `PlayStore.clearSlot`,
  `store.ts:199`) и запись в памяти `saved`. Партия целиком: ходы, заметки, время, подсказки, у Лжеца — секрет и
  обвинения. **Не** трогаются: последняя выбранная сложность режима (`picks`), история поимок Лжеца (`liarHistory`
  пишется только при решении), записи дней, Year, постоянная сетка.
- **Живая партия на хабе.** Если удаляемый режим — та партия, что «запаркована» в `snap` (вышли на хаб тапом по
  вкладке: `snap.mode === mode`, `hasSlot()`), её тоже надо сбросить (`resetToLoading({ hub: true, … })`), иначе
  `open(mode)` вернёт удалённую. Предлагаю `PlayStore.discard(mode): SavedPlay | null` (возвращает запись для
  отмены) и `PlayStore.restore(rec)` (`saved.set` + `setMeta(slotKey(mode), rec)`).
- **Синк — вопрос developer'у (§A12).** По коду `sync/*` ключи `playGame:*` не читает, то есть слоты свободных
  партий на сервер не уходят и удалять там нечего. Подтвердить; если они всё же в снапшоте — удаление должно
  уйти тем же путём, что «Новая сетка» (`clearSlot`), и отмена — тем же, что обычная запись слота.
- Удаление пишется **сразу** (не «после тоста»): убитое во время тоста приложение — партия удалена, как и видел
  пользователь. «Отменить» записывает сохранённую копию обратно.

## A7. После удаления: undo-тост или подтверждение

### A7.1 Рекомендую и даю дефолтом — undo-тост

**Почему:** (1) HIG `alerts.md`: «Avoid displaying alerts for common, undoable actions, even when they're
destructive» — а удаление партии мы делаем отменяемым. (2) Нативный образец — Почта/Заметки/Файлы: полный свайп
удаляет сразу, без вопроса. (3) Подтверждение после полного свайпа превращает быстрый жест в два действия и
приучает нажимать «Удалить» не читая — у тоста ошибка исправляется одним тапом без лишнего шага у всех остальных.
(4) Потеря невелика и обратима в окне 6 с; партии свободной игры не попадают в Year («Свои игры не попадают в ваш
год»).

| | Значение |
|---|---|
| Место | над таб-баром: `bottom = высота таб-бара + 8 px`, поля 16 px (`max(16px, safe-area)`), во всю ширину между полями |
| Вид | поверхность `--card`/`--elev`, радиус 14, тень `0 8px 28px rgba(0,0,0,.16)` (dark `.6`) + контур 0,5 px `--hairline`; текст `--label` 0.94rem, кнопка «Отменить» `--ink` semibold, цель ≥ 44×44. Непрозрачный — Reduce Transparency не нужен |
| Текст | «Сетка „Лжец“ удалена» (§A9). Без таймера-полоски |
| Время | **6 с**; пауза, пока палец на тосте или фокус внутри |
| Путь клавиатуры/VoiceOver | если удаляли с клавиатуры/AT (`click.detail === 0` или из «клавиатурного» открытия строки): фокус переходит на «Отменить», тост **не исчезает по таймеру**, пока фокус в нём; ушёл фокус — 6 с заново (WCAG 2.2.1) |
| Объявление | текст тоста — в `aria-live="polite"` регион; после «Отменить» — «Сетка „Лжец“ восстановлена», фокус — на строку режима |
| Закрывается (удаление окончательно) | 6 с; новое удаление (старая отмена теряется, тост заменяется); переход с хаба (открыта партия, шит режима, другая вкладка, Settings); `visibilitychange: hidden`. **Не** закрывается от прокрутки хаба |
| «Отменить» | слот записан обратно, строка снова «● Не закончена …» (кроссфейд 160 мс × `--mk`), тост уходит |
| Слои | выше хаба и таб-бара, ниже меню/шитов/затемнений (открытие меню/шита закрывает тост) |
| Компонент | новый (`UndoToast`, в `shell/`) — в приложении тостов пока нет |

### A7.2 Альтернатива — подтверждение (если владелец выберет)

После полного свайпа или тапа «Удалить» строка остаётся открытой, снизу — action sheet (существующий
`recovery/ActionSheet`): заголовок «Удалить незаконченную сетку?», сообщение «Лжец · Сложно · осталось 47 · 03:18.
Это нельзя отменить.», красная «Удалить» вверху группы (HIG `action-sheets.md`: destructive — сверху), отдельная
«Отмена» — **фокус по умолчанию на «Отмене»**. «Удалить» → удаление без тоста + объявление; «Отмена»/тап вне/Esc →
строка закрывается, партия на месте. В макете — переключатель «Confirm sheet».

## A8. Без жеста: клавиатура, VoiceOver, Switch/Voice Control

Правило HIG `accessibility.md`: «Offer alternatives to gestures». У веб-страницы нет нативных VoiceOver custom
actions (ротора «Действия»), поэтому два видимых для AT пути:

1. **Контекстное меню строки (уже есть — `ModeMenu`)**: последним пунктом, отделённым толстым разделителем
   (6 px фоном `--bg`), — **«Удалить сетку»** красным (`--wax`) со значком корзины (HIG `context-menus.md`:
   деструктивное — в конце и красным). Только если у режима есть партия. Работает долгим нажатием, правой кнопкой,
   клавишей «Меню»/Shift+F10, и у VoiceOver — двойным тапом с удержанием (жест «пропускается» к странице).
2. **Кнопка удаления в DOM всегда** (не только в открытом состоянии), сразу за строкой:
   `aria-label="Удалить незаконченную сетку: Лжец"` — содержит видимое слово «Удалить» (WCAG 2.5.3). Визуально
   под строкой. VoiceOver: следующий элемент после строки, двойной тап удаляет → фокус на «Отменить».
   Voice Control: «Нажать Удалить…».
3. **Клавиатура:** Tab со строки переводит фокус на её кнопку «Удалить» — **строка сама открывается** (то же
   состояние `open`, кольцо фокуса внутри красного, 2 px `--on-wax`, отступ −5 px). Delete/Backspace на строке с
   партией — то же. Enter/Space — удалить (→ фокус на «Отменить»). Esc — закрыть, фокус на строку. Ушёл фокус —
   строка закрылась. Касание кнопку не фокусирует для этого пути (открытие по фокусу — только после клавиши).
4. Строки **без** партии кнопки не имеют (`hidden`) — в порядке чтения ничего лишнего.

| `modes.deleteMsg` — только A7.2 | {{mode}} · {{meta}}. This can’t be undone. | {{mode}} · {{meta}}. Це не можна скасувати. | {{mode}} · {{meta}}. Это нельзя отменить. |

«Undo/Скасувати/Отменить» — как существующий `undo` (`en.json:238`, uk/ru `:250`); «Отмена» в шите — существующий
`modes.cancel`. Слово «сетка/сітка/puzzle» — как в существующем `modes.discard`. `{{mode}}` — `modes.<id>.name`,
`{{meta}}` — `slotMeta`.

## A10. Цвет, тёмная тема, 320, AX3

- **Красный — существующий `--wax`** (единственный красный системы; HIG `buttons.md`: деструктивная кнопка —
  системный красный). Подпись — **новый алиас `--on-wax`**, без нового hex: светлая `#FFF` на `#B3261E` = **6,5:1**;
  тёмная `#000` на `#FF6B5E` = **7,5:1** (белый там дал бы 2,8:1 — не проходит); `prefers-contrast: more` dark —
  `#000` на `#FF8F85`, выше. Так же устроен `--on-ink` (в тёмной — чёрный на светлых чернилах). Спорный момент:
  сургуч задуман «только для ошибки»; деструктивное действие — ближайший смысл, отдельный красный был бы вторым
  оттенком красного на экране. Пересматривать можно, блокером не считаю.
- **320 pt:** `W = 288`, кнопка 86–104 px, `T` 158–176 px; тост в одну строку на en/ru, uk может перенестись в 2.
- **AX3:** строка режима уже колонкой (PD-167) и выше — красный на всю её высоту, значок по центру; кнопка
  переходит в значок по правилу `0,45·W`; тост — столбцом: текст сверху (переносится), «Отменить» справа под ним;
  шит A7.2 — заголовок и сообщение переносятся, кнопки 56+ px.
- **Тёмная:** тост `--elev #1C1C1E` на `#000` — граница даётся контуром `--hairline`, не только тенью.
- Кадры всех этих случаев — `design/pd224-shots/` (список в шапке скрипта).

## A11. Приёмка для PD-225/PD-226

Живые (Playwright, chromium + webkit; в `pd224-shots.mjs` эти же проверки на макете, функция `gestures`):
1. Свайп > A/2 → `open`, партия на месте; < A/2 → закрылась.
2. Тап по другой строке при открытой → закрылась, другая **не** открылась.
3. Полный свайп → слот `null` в IDB, строка с описанием, тост; «Отменить» → слот восстановлен байт в байт (сравнить JSON).
4. Вперёд за `T` и назад ниже `T − 24` → не удаляет.
5. Вертикальный жест под углом > 34° → строка не двигается, хаб прокручивается.
6. Слева направо на закрытой; свайп строки без партии; строки «Продолжить» → ничего.
7. Клавиатура: Delete на строке → кнопка в фокусе, строка открыта; Enter → удалено, фокус на «Отменить», тост не гаснет, пока в фокусе.
8. Меню долгого нажатия → «Удалить сетку» красным последним пунктом → удаление + тост.
9. Удаление «запаркованной» партии (вошли в Лжеца → тап по вкладке Play → свайп Лжеца) → тап по строке открывает **шит режима**, а не удалённую партию.
10. Reduce Motion: доводки мгновенные, кадры совпадают по виду; 320 и AX3 без переполнения; light/dark.
Юнит: функция решения по отпусканию (`x, v, armed, A, T`) — таблица §A3.

iPhone владельца (агенты не могут; пункты в чек-лист):
1. Свайп строки «Лжец» влево до середины — видна красная «Удалить», строка держится; дальше до конца и отпустить — удалилась, внизу «Отменить».
2. Медленная прокрутка хаба пальцем, начатая на строке с партией (в том числе слегка по диагонали), — строка не едет.
3. VoiceOver: после строки «Лжец, не закончена…» свайпом вправо — кнопка «Удалить незаконченную сетку: Лжец».
4. В установленном приложении провести от левого края экрана вправо на Settings — убедиться, что системного «назад» нет (нужно для части B).
5. Удержание строки — меню с красным «Удалить сетку», текст не выделяется.
