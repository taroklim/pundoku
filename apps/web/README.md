# @pundoku/web

PWA-клиент Pundoku: React 19 + Vite + i18next (en/uk/ru). Экраны: Today (PD-12), Play (PD-11), Year (заглушка).

```sh
pnpm dev:web            # vite :5173, запросы /api/* проксируются на localhost:3000 (apps/api)
pnpm --filter @pundoku/web build && pnpm --filter @pundoku/web exec vite preview   # прокси работает и в preview
pnpm --filter @pundoku/web test                                                    # vitest
```

`VITE_API_BASE_URL` (build-time) — base URL api. Пусто — тот же origin (dev-прокси Vite). В проде — публичный
адрес api без завершающего `/`; `WEB_ORIGIN` api должен содержать origin web. Service worker не кэширует `/api/*`
(`navigateFallbackDenylist`).

## Экран Today (PD-12)

Игровая механика (ввод, заметки, undo, таймер, M1/M3, лог ходов) — общая с Play: `play/gameStore.ts`
(`GameStore`), общие UI-части — `play/controls.tsx`, карточка результата — `play/ResultCard.tsx`.
`PlayStore` берёт сетку из Worker-генератора, `DayStore` (`today/dayStore.ts`) — из API либо фолбэка.
Сторы живут выше вкладок: смена вкладки партию не сбрасывает (таймер на паузе, пока вкладка не на экране).

### Какая сетка дня играется (`today/dayResolver.ts`, чистый модуль, тесты `dayResolver.test.ts`)

Дата — **локальная** дата устройства (`YYYY-MM-DD`). Сервер принимает до «завтра» по UTC включительно.

1. Сетка дня — ответ `GET /api/daily/:date` (`mission`, `difficulty`, `winRate?`, `source: sudoku.com | generator`).
   Решение клиент вычисляет сам: `solve(mission)` движка (сервер `solution` не отдаёт). `mission` без решения
   (противоречивая сетка) трактуется как «ответа не было». **Единственность решения клиент не проверяет**:
   `solve` берёт первое найденное решение. Осознанно: сетки Sudoku.com и генератора единственны (проверено
   2026-09-29 на 45 последних днях реального API Sudoku.com — 45/45 `countSolutions === 1`, найденное решение
   совпало с `solution` из ответа), а неединственная сетка не должна ломать день «нет ответа».
2. **Нет ответа** (офлайн, 5xx/404/429, таймаут 8 с, невалидный JSON) — клиентский фолбэк, и **только**
   `dailyPuzzle(date, difficulty)` движка (в Web Worker: для тяжёлых сложностей это секунды). `difficulty`:
   из ответа API, если он был **и `source: generator`**; иначе последняя известная за сессию (тоже только у
   `generator`); иначе `DAILY_FALLBACK_DIFFICULTY` (`medium`). Метка сложности Sudoku.com (`hard`/`expert`…) —
   чужая шкала, не сложность генератора: она не запоминается и в фолбэк не идёт, иначе после смены суток в
   офлайне одна дата давала бы разные сетки в зависимости от истории сессии (`dailyPuzzle(date,'hard')` против
   `dailyPuzzle(date,'medium')` на сервере). Для подписи метка Sudoku.com при этом показывается как есть.
   Seed вручную не собирается — сетка обязана совпасть с серверным фолбэком.
   Константа заведена в web отдельно: движок её не экспортирует, значение должно совпадать с `DAILY_FALLBACK_DIFFICULTY`
   сервера (`apps/api`, по умолчанию `medium`).
3. **Медленный сервер**: API отвечает дольше 2,5 с — начинаем играть фолбэком; поздний ответ сверяется по п. 4.
   Офлайн (`navigator.onLine === false`) фолбэк без ожидания.
4. **Сверка при возврате в сеть** (событие `online`, возврат вкладки/приложения на экран): день перезапрашивается
   (`fetch` с `cache: "no-cache"` — фолбэк-сетка отдаётся с `max-age=60`) и сверяется по `mission`/`source`:

   | Ситуация | Что делаем |
   |---|---|
   | Ответа нет | остаёмся как есть (помечаем «офлайн») |
   | Та же `mission` | обновляем `source`/`winRate`, проверка решения — на сервере (`POST verify`) |
   | Другая `mission`, ходов нет | молча берём актуальную сетку |
   | Другая `mission`, ходы есть | доигрываем свою; проверка **локальная** (verify на сервер не шлём), win rate не показываем |

   «Ходы» — любая запись в логе (цифра, стирание, заметка, undo). Сетка `sudoku.com` неизменна — её не перезапрашиваем.
   Смена суток: если день не начат либо решён, при возврате на экран грузится новый день; начатый вчерашний доигрывается.
   **Таймера на полночь нет — осознанно**: смена дня замечается только по событию `online` / `visibilitychange`
   (или следующей загрузке экрана). iOS при возврате из фона (в т. ч. PWA) присылает `visibilitychange`, а держать
   таймер в свёрнутой PWA бессмысленно (iOS его замораживает); открытый после полуночи экран продолжает показывать
   вчерашний день до первого такого события.
5. **Решение** проверяется на сервере (`POST /api/daily/:date/verify`) только для сетки, совпавшей с серверной;
   ответ `false` скрывает «N % solved today». Нет ответа — день всё равно решён (проверено локально).
6. Подпись «Wed 29 Sep · Medium · 4:12». Если сложность источника движку неизвестна — без сложности.
   Ярлык источника (минимальный, без бренд-ассетов): «Puzzle from Sudoku.com» / «Puzzle from Pundoku's generator» /
   «Made on this device» (клиентский фолбэк).
7. Прогресс дня сохраняется в репозитории (см. ниже) и переживает смену вкладки; решённый день финален
   (без сети и анимации сразу карточка).

### Карточка дня (после решения)

`ResultCard`: тепловая карта `heatmap(moveLog)` (в макете — «Your path»; время движка переводится в ранги, чтобы
одна долгая пауза не сжала карту в два оттенка), «Technique reached» (`summary`), время, clean/число правок,
«N % solved today» — только после решения и если API отдал `winRate` для этой сетки. **Share неактивна** (TODO,

### Grid ∞ — постоянная сетка (`today/permanent.ts`, `repository.ts`)

Концепция — `reports/sudoku-pwa-research/07-concept-draft.md`: у сетки с самого начала скрытое решение; игрок
управляет позицией (клетка последнего хода решённой сетки дня), цифра берётся из скрытого решения.

**Решения developer'а** (концепция их не фиксирует — ждут подтверждения PM/владельца):

- Скрытое решение: `generate({ difficulty: "easy", seed: "grid-inf/<installSeed>/<index>" }).solution`.
  `installSeed` — случайный на установку; позже синхронизируется с сервером (PD-14).
- Позиция: клетка последнего хода лога дня. Занята — ближайшая свободная по Манхэттену, при равенстве — меньший индекс.
- Один «улёт» на дату; повторное решение той же даты (Play не считается) клетку не добавляет.
- «Now solvable» — `countSolutions(подсказки, 2) === 1` (не раньше 17 клеток); показывается тихо в подписи секции.
- Бесконечность: `nextGrid` (следующий индекс с пустым набором). UI решения Grid ∞ нет (экрана в утверждённом макете
  нет), поэтому правило «каждая следующая сетка требует больше открытых клеток» пока не применяется — открытый вопрос.

Хранение — интерфейс `ProgressRepository` (`getDay/saveDay/getPermanent/savePermanent`), сейчас
`InMemoryProgressRepository`: **без localStorage/IndexedDB, за перезагрузкой страницы данные не переживают** —
осознанно; IndexedDB и сервер (анонимный аккаунт) — PD-14 подставит свою реализацию без правок экрана.

### M5 «улёт» последней клетки

Данные гаснут (200 мс) → карточка → цифра клетки дня летит с поля в целевую клетку Grid ∞ (340 мс) → сплошное кольцо
и «толчок» 260 мс. Всего ≤ 600 мс; любое касание прерывает и сразу показывает итог
(`today/useSolveSequence.ts`). `prefers-reduced-motion`: без полёта — карточка кроссфейдом, целевая клетка
подсвечивается кольцом. Возврат на вкладку и перезагрузка экрана анимацию не повторяют.
