# Самопроверка iPhone-чек-листа Pundoku (PD-82)

Скрипты прогоняют пункты 1-51 из `STATUS.md` («Проверки для владельца на iPhone 16») в Playwright WebKit с эмуляцией iPhone 16
(393x852 pt, DPR 3, touch, mobile) на реальной сборке (`pnpm build`) в отдельном worktree и отдельной БД. Основной чекаут, прод, порт 8090 и
порты QA (3500/5500) не затрагиваются. Артефакты и скриншоты лежат в `/tmp/pundoku-ios/` (в репозиторий не попадают).

## Подготовка (один раз)

```bash
# 1. worktree от main (из основного репозитория)
git worktree add --detach /tmp/pundoku-ios/wt main
# 2. Playwright со своим webkit - вне репозитория
mkdir -p /tmp/pundoku-ios/pw && cd /tmp/pundoku-ios/pw && npm init -y && npm i playwright && npx playwright install webkit
# 3. стенд: createdb pundoku_ios, install, build, migrate, запуск api:5600 и web:3600
products/pundoku/docs/ios-selfcheck/stack.sh up
```

## Прогон

```bash
cd products/pundoku/docs/ios-selfcheck
node selfcheck.mjs            # все секции s1..s5
node selfcheck.mjs s4 s5      # только выбранные
```

Секции: `s1-shell` (пункты 1-12), `s2-play` (13-22), `s3-year` (23-33), `s4-settings` (34-46), `s5-ink` (47-51). Пункт 52 (calc() в keyframes при «Уменьшить движение», PD-81) — только на телефоне, скриптом не проверяется.
Каждая проверка печатает `ok` / `FAIL` с пояснением; итог по секциям - в `/tmp/pundoku-ios/art/results-<секции>.json`.

## Перезапуск и остановка

| команда `stack.sh` | что делает |
| --- | --- |
| `up` | создаёт БД, ставит зависимости, собирает, мигрирует, запускает api и web |
| `start` | запускает уже собранное (если api не запущен) |
| `down` | останавливает api и web (только по записанным в `/tmp/pundoku-ios/run/*.pid`; `pkill` по имени не используется) |
| `web-down` / `web-up` | останавливает/запускает только web (так имитируется «нет сети» для service worker) |
| `reset-db` | очищает таблицы стенда |
| `drop` | останавливает свои процессы и делает `dropdb pundoku_ios` |

Лимиты api (на IP/устройство: `/api/devices` 10/мин, `/api/daily` 60/мин, выпуск ключа 5/час, неверные ключи 20/час) хранятся в памяти api.
Если секция упала на 429, выполните `stack.sh down && stack.sh start` и повторите. Между повторными прогонами `s4` перезапускайте api.
Переменные: `WT`, `DB`, `API_PORT`, `WEB_PORT`, `RUN` (для `stack.sh`); `BASE`, `API`, `WT`, `ART`, `PW_DIR` (для скриптов).

Уборка в конце: `stack.sh drop`, затем из основного репозитория `git worktree remove --force /tmp/pundoku-ios/wt`.

## Чек-лист для владельца

`build-checklist.mjs` собирает самодостаточный `../ios-checklist.html` (вердикты по пунктам заданы в его списке `ITEMS`; при изменении результатов правьте там и
запускайте `node build-checklist.mjs`). `selftest-checklist.mjs` проверяет файл в webkit 390x844: светлая/тёмная тема, цели касания, шрифт >= 16 px,
отметка и заметка переживают перезагрузку, копирование результата и запасной путь (выделение текста), нет горизонтального скролла и сетевых запросов.
Стенд ему не нужен.

## Что эмулируется и с какими оговорками

- Safe area: webkit не умеет `env(safe-area-inset-*)`, поэтому ответ `**/assets/*.css` переписывается (подставляются 59 сверху и 34 снизу в портрете, 59 по бокам и 21 снизу в ландшафте).
- «Уменьшить прозрачность»: Playwright не включает этот режим, поэтому в CSS правило `prefers-reduced-transparency` форсируется подменой условия. Реакцию iOS на настройку проверить нельзя.
- Dynamic Type: подменяется размер корневого шрифта (L = 17 px, AX5 = 53 px). Приложение берёт размер из `font: -apple-system-body`; то, что iPhone реально передаёт размер в установленное приложение, эмуляция не показывает.
- Видимость страницы (свернуть/вернуться) - подменой `document.visibilityState`; офлайн для service worker - остановкой web, для API - `page.route(... abort)`; смена даты/полуночи - подменой часов.
- Не проверяется эмуляцией: установка PWA и иконка/заставка, реальные хаптики и жесты Safari, стекло `backdrop-filter` на устройстве, реальные отступы выреза, VoiceOver, два настоящих устройства, реальный буфер обмена в standalone, режим полёта в установленном приложении, системный share-sheet.
- Сетка дня на стенде всегда из генератора: адрес Sudoku.com намеренно мёртвый, чтобы стенд был детерминирован.
